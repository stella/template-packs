# Stella template packs

Content repository of legal template packs for [Stella](https://github.com/stella/stella), the open-source legal workspace. Stella bundles this repository and offers the packs to users, filtered by jurisdiction, as an optional install.

Each pack is a directory under `packs/` with its own license, a `pack.json` manifest and one directory per template holding a fillable DOCX and a README. `index.json` at the root is generated from the packs and is the only file a consumer needs to read to list what is available.

## What a pack is

```
packs/<pack-id>/
  pack.json                       # manifest (schema/pack.schema.json)
  LICENSE                         # content license of this pack
  templates/<slug>/
    template.docx                 # fillable DOCX: {{field}} merge fields + Stella manifest
    README.md                     # purpose, when to use, assumptions, fields, review notes, source, changelog
    template.md                   # optional readable rendering of the DOCX
```

`pack.json` fields:

| Field | Meaning |
| --- | --- |
| `id` | Pack identifier, equal to the directory name (lowercase kebab-case). |
| `name`, `description` | Display name and one-paragraph description. |
| `version` | Semantic version of the pack contents. |
| `license`, `licenseUrl` | SPDX identifier of the content license and a link to its text. |
| `source` | Where the originals came from: `name`, `url`, `retrievedAt` (date). |
| `authors` | `name`, optional `organization` and `url`, `role` (`drafter`, `reviewer`, `converter`), optional `date`. |
| `jurisdictions` | `[{ country: ISO 3166-1 alpha-2, subdivision?: ISO 3166-2 }]`; an empty array means jurisdiction-agnostic. `EU` is accepted for the European Union as a whole. |
| `languages` | BCP-47 tags. |
| `legalAreas` | Lowercase kebab-case areas, e.g. `data-protection`. |
| `lastReviewedAt` | Date the source content was last reviewed by its drafters (or the source's last content change; the pack README says which). |
| `disclaimer` | Shown to users before install. |
| `templates` | `slug`, `title`, `file`, `readme`, and optional per-template `jurisdictions`, `languages`, `legalArea`, `license` overrides. |

The schema is strict (`additionalProperties: false`); `jurisdictions`, `languages` and `authors` are required arrays.

### Fillable DOCX

A template DOCX contains `{{fieldName}}` merge fields (camelCase; one field per distinct value, reused wherever that value appears) and a Stella template manifest: a custom XML part in the namespace `urn:stella:template:v1` declaring each field's label, input type (`text`, `date`, `number`, `select`, `boolean`), required flag and help text. The manifest format is defined in Stella (`apps/api/src/lib/docx/template-manifest.ts`). Validation requires the set of manifest fields to equal the set of markers in the document.

## index.json

Generated by `scripts/build-index.ts`; CI fails when it is stale. Shape:

```jsonc
[
  {
    "id": "general-legal",
    "name": "…",
    "version": "1.0.0",
    "license": "CC0-1.0",
    "jurisdictions": [{ "country": "US" }],
    "languages": ["en"],
    "legalAreas": ["…"],
    "authors": [{ "name": "…", "role": "drafter", "url": "…" }],
    "templateCount": 12,
    "templates": [
      {
        "slug": "mutual-nda",
        "title": "Mutual Non-Disclosure Agreement",
        "file": "templates/mutual-nda/template.docx",   // relative to packs/<id>/
        "license": "CC0-1.0",                           // effective (template override or pack)
        "jurisdictions": [{ "country": "US" }],         // effective
        "languages": ["en"],                            // effective
        "legalArea": "confidentiality",                 // or null
        "fields": ["companyName", "effectiveDate", "…"],
        "sha256": "<sha256 of template.docx>"
      }
    ]
  }
]
```

## Contributing a pack

1. Open a PR adding `packs/<pack-id>/` with `pack.json`, `LICENSE`, and `templates/<slug>/template.docx` + `README.md` for each template (plus `template.md` if useful).
2. Run `bun install && bun run check` locally; CI runs the same: `scripts/validate.ts` then `scripts/build-index.ts --check`. Commit the regenerated `index.json`.
3. Licensing: only permissive content licenses are accepted (`CC0-1.0`, `CC-BY-4.0`, `MIT`). The pack `LICENSE` file must be the full license text, and `pack.json` must name the source and authors. For `CC-BY-4.0` the attribution the licensor requires must appear in each template README.
4. Attribution: name the original drafters and the source URL in `pack.json` and in every template README, even when the license does not require it. List the converter separately (`role: "converter"`). Do not rewrite the legal text of a source template in a conversion; placeholders become fields, optional passages are documented in the README's review notes.
5. Each template README covers: purpose, when to use, assumptions (jurisdiction, perspective, defaults), the field list with help text, review notes (what remains to be checked or deleted by hand), source and license, changelog.
6. Versioning: bump the pack `version` on every content change (patch for README/metadata, minor for new templates or fields, major for removed or renamed templates or fields).

Conversion scripts that depend on a Stella checkout live under `scripts/convert/`; each documents how to run it.
